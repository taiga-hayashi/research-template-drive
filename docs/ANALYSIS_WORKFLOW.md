# 解析・作図の運用

## NotebookとPythonをセットにする

各解析分類に `plot.ipynb` と `plot.py` を必ず2つセットで置く。両方から同じ入力・条件・共通処理を実行できるようにし、共有実装は `src/` または `scripts/` にまとめる。片方を変更したらもう片方との一致を確認する。

Notebookでは入力、条件、検証、作図、結果確認、保存記録をセルで追えるようにする。各端末のDrive外にある既存Python環境を使って先頭から実行し、図と主要な検証結果をセル出力として保存する。スクリプトを実行しただけでNotebook実行済みと記録しない。未実行・一部実行・目視未確認は明記する。既存環境を勝手に作り直したり、Drive内へ仮想環境を作成したりしない。

## 図の見方をMarkdownに書く

各図の直前のMarkdownに、何を示すか、縦横軸・単位、色・線・点・誤差の定義、run/seed/checkpoint等の集計単位、比較する箇所、指標の大小の意味、解釈の限界を書く。省略語は初出で説明し、相互作用の符号と目的値全体の良し悪しを混同しない。図の共通表示方針は [FIGURE_POLICY.md](FIGURE_POLICY.md) に従う。

既存図のコピーは参考資料と区別する。再作図の依頼では入力データ・条件・コードからPNG/PDFを実際に生成し、画像を表示するだけで再作図済みとしない。保存済みCSVからの再作図と、学習やcheckpointからの指標再計算は別々に記録する。

## 固定した場所へ保存する

```text
analysis/<study>/<category>/
  README.md               # 役割・入出力・入口
  plot.ipynb
  plot.py
  analysis_config.json    # 現在のanalysis_id・入力checksum・条件・環境
  results.md              # 現在の結果・解釈・検証状態
  csv/
  png/                    # 必要なpanels/も独立描画
  pdf/                    # PNGと同名・同じ相対パス
```

分類名は短くし、`optimization`、`prediction`、`interactions` など役割が分かる名前を使う。`v01`・`v02` やanalysis_idの名前の出力フォルダを再実行ごとに増やさない。再実行では同じ `pdf/`・`png/`・`csv/` の生成ファイルを更新する。分類の役割を説明するREADMEと、実行結果のresults.mdを分ける。

解析試行ごとに新しいanalysis_idを発行し、設定・索引で識別する。更新前に旧実行の条件、入力checksum、コード版・実行時ソース、環境、検証状態、出力checksumを `docs/records/analysis_runs/<analysis_id>.json` 等の記録ファイルへ保持する。旧実行の索引参照先もその記録へ向け、現在の生成ファイルを過去の結果と誤認させない。失敗・未完了の試行も記録し、以前の図が残っていても成功扱いにしない。

生データ・入力原本・実験run・checkpoint・保存パッケージは上書きしない。Macとサーバーから同じ解析先を同時に更新しない。固定配置は今後の生成先の規則であり、既存フォルダの一括移動・改名は自動実施しない。

これらは運用上の要件であり、このテンプレートがNotebookの自動実行、旧実行情報の保存、索引更新を実装しているわけではない。各研究の解析コードで対応し、実際の検証状態を記録する。
