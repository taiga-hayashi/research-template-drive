# 設計判断ログ

## 2026-10-17: フォルダ別の役割とルールを明文化
全既存フォルダへREADMEを追加し、置くもの・置かないもの・命名・保存・参照のルールを記載する。フォルダ案内から横断参照できるようにし、data/cache/tmp/archiveのデータ除外を維持しつつ説明READMEのみGitへ登録する。既存プロジェクトのデータ配置・実験条件は変更しない。

## 2026-10-17: サーバー梱包と解析データの選択取得を実装
明示したsource→target対応からZIP64パッケージと内部manifestを作成し、SHA-256を検証する。取得は既存rcloneを使い、必要packageだけを専用領域へ検証後に復元する。元データ・既存run・認証設定は変更せず、旧tarは取得と全体checksum照合のみ対応する。

## 2026-10-17: 状態・ジョブ・引継ぎ・比較・図・確認実験を追加
計算終了と研究上の検証完了を分け、索引と状態記録にvalidation、package validation、analysis、overallの状態を追加する。ジョブ再開とAI引継ぎの雛形、研究固有の比較条件表・共通図設定・探索/確認/診断protocolを用意する。数値条件・統計手法・ジョブ管理ツールは一律に固定しない。既存の研究データや環境は変更せず、自動ジョブ投入・転送・検証の実装は別作業とする。

## 2026-10-17: 各端末の既存ローカル仮想環境を使用
Python実行はDrive外の既存環境を利用する。Macとサーバーで.venv本体を共有・転送せず、依存定義と実際の環境版を記録する。環境の新規作成・更新はこの方針の追記では行わない。

## 2026-10-17: サーバー計算と複数端末での解析に対応
課題: 計算結果は研究室サーバーからDriveへ直接保存され、解析はMacでもサーバーでも行うため、Macでの実行を標準にした説明では不足していた。
判断: 端末の保存先と研究・解析条件を分離する。実験・解析索引とanalysis_idを導入し、結果・checkpoint・解析入力・コード版・Drive保存検証を対応付ける。新規ZIPを標準とし、既存tar等も保持する。
影響: テンプレートと今後の新規作業。PestControlの既存フォルダ・条件・結果を移行しない。前のMac中心の標準をこの方針で更新する。
代替案: 解析場所を片方に限定する方法は採らず、共通コードと端末別パスを使う。認証・転送の自動化は別作業とし、今回は実装しない。

## 2026-10-17: Drive同期フォルダでの直接作業を標準化
課題: 初版は成果物の事後転送を中心に説明しており、MacのDrive同期フォルダを直接編集・実行する運用が不明瞭だった。
判断: Drive内でコード・設定・文書・閲覧用成果物を直接扱い、ZIPは実験時点の再現用snapshotとして併用する。大量出力・仮想環境・キャッシュはDrive外を使う。研究用GitHubリポジトリは任意とする。
理由: 日常の編集方法を保ちつつ、大量の小ファイル同期と実験時点の記録消失を避けるため。
影響: 新規研究の手順・保存ルール。既存フォルダ・run・条件hash・結果は変更しない。
代替案: 全小ファイルの直接同期、または全作業をDrive外に移す方式。直接閲覧と同期負荷の両方を考慮し、対象ごとに保存方法を分けた。

## 2026-10-17: Drive研究管理標準v1
共通コード・実験・解析を分離し、条件hashとrun IDで結果を識別する。Driveへの転送は実験単位のZIP＋閲覧用要約とする。DVCは任意。詳細はRESEARCH_LAYOUT.md。
